# TeamFlow 架构决策

## Agent 与副作用分离

LangGraph 只产生 `proposed` 行动项，不能直接调用任务和日历工具。行动项可以来自结构化 LLM 或规则基线；模型的 `source_quote` 必须逐字存在于会议记录，失败时回退并计数。人工审批接口检查选中项是否有负责人和截止日期，成功后才把状态改为 `approved`。工具层只读取已批准或已执行的项目，因此 UI、Agent 或重复请求都不能绕过同一后端闸门。

## 幂等策略

幂等键为：

```text
meeting_id : action_id : tool
```

键在 SQLite `artifacts` 表中唯一。首次调用创建稳定的模拟外部 ID；重试返回相同记录并标记 `created=false`。生产系统还应把该键传给支持幂等的第三方 API，并处理“远端成功、本地超时”的对账。

## MCP 的职责

`mcp_server.py` 通过 stdio 暴露任务和日历 payload 生成工具，HTTP 执行器与 MCP 共用 `tool_payloads.py`。MCP 只是传输适配层，不拥有审批权限；真正的状态检查仍在服务端仓库和执行器中。

## 生产化扩展点

1. 为模型抽取建立人工标注集并比较不同模型、提示词和规则基线。
2. 接入转写服务并明确个人信息、录音授权和保存期限。
3. 为审批增加用户身份、角色权限和组织租户隔离。
4. 为 Jira、飞书、钉钉或日历实现独立适配器及补偿操作。
5. 加入远端对账、死信队列和审批撤销，而不是自动无限重试。
